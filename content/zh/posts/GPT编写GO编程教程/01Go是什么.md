引言

如果你刚开始接触 Go，可能会先遇到一个问题：

«为什么要学习 Go？»

毕竟现在已经有很多成熟的编程语言。

想写脚本，可以使用 Python；
想开发 Web 应用，可以使用 Java、JavaScript、C# 等语言；
想追求极致的底层控制，可以使用 C 或 C++；
想要内存安全和现代语言特性，还有 Rust。

那么，Go 又解决了什么问题？

如果只是把 Go 当成另一门“换一种语法写程序”的语言，那么很容易在学习过程中失去方向。

实际上，Go 的价值并不只在于语法简单，而在于它试图解决一个非常现实的问题：

«如何让软件工程师能够用一门相对简单的语言，构建规模较大、性能可靠、能够并发运行，并且容易部署和维护的软件系统？»

这也是理解 Go 的一个重要入口。

本文不会马上开始讲变量、循环和函数，而是先回答几个问题：

- Go 是什么？
- Go 为什么会出现？
- Go 的设计目标是什么？
- Go 和其他常见语言有什么不同？
- Go 适合开发什么？
- 学习 Go 时应该建立怎样的思维方式？

读完这篇之后，我们再开始真正写 Go 程序。

---

一、Go 是什么？

Go，也叫 Golang，是一门由 Google 开发的通用编程语言。

Go 最初由 Robert Griesemer、Rob Pike 和 Ken Thompson 等人参与设计。

Go 的公开版本在 2009 年正式发布。

从语言分类来看，Go 具有几个非常明显的特点：

特征| Go
类型系统| 静态类型
编译方式| 编译型
内存管理| 自动垃圾回收
并发模型| Goroutine + Channel
语法风格| 简洁、克制
标准库| 完整
部署方式| 通常可以编译为单个可执行文件
开源| 是

这些信息本身并不难。

真正值得思考的是：

«为什么 Go 要把这些特性组合在一起？»

要回答这个问题，就必须回到 Go 出现的时代背景。

---

二、Go 为什么会出现？

Go 的诞生和大型软件工程的发展有很大关系。

随着软件系统规模不断扩大，开发者面对的问题已经不再只是：

«“这段代码能不能运行？”»

而开始变成：

«“几百个人一起开发这个项目时，它还能不能维护？”»

进一步还会出现：

- 项目越来越大，编译越来越慢；
- 代码越来越复杂，新成员越来越难上手；
- 多线程编程越来越困难；
- 服务数量越来越多；
- 软件部署越来越复杂；
- 服务器数量越来越多；
- 开发效率和运行效率之间越来越难平衡。

传统语言各有自己的优势，但也各有代价。

例如 C 和 C++ 可以提供非常强的性能和控制能力，但语言和工程体系本身也相对复杂。

Java 等语言拥有成熟的运行时和庞大的生态，但在某些类型的系统开发中，开发和部署方式又可能显得比较重。

而 Python 等动态语言拥有非常高的开发效率，却通常需要在运行性能、类型约束等方面做不同的取舍。

Go 的设计者面对的核心问题之一，就是：

«能不能设计一门语言，让大型软件系统的开发变得更加简单，同时又拥有足够好的运行性能？»

Go 的很多设计决定，都是围绕这个问题展开的。

---

三、Go 的设计哲学：少一点复杂，多一点直接

学习 Go 时，你会发现一个非常明显的特点：

«Go 不喜欢复杂。»

这并不意味着 Go 功能少，而是它倾向于用较少的语言机制解决问题。

例如，Go 的语法中没有传统意义上的类继承体系。

它也没有大量复杂的语法糖。

Go 甚至没有传统的 "while" 关键字。

循环主要使用：

for i := 0; i < 10; i++ {
    fmt.Println(i)
}

看起来非常简单。

Go 的设计者并没有试图让语言拥有尽可能多的功能，而是更加关注：

- 代码是否容易阅读；
- 代码是否容易理解；
- 不同开发者写出的代码是否容易保持一致；
- 工具是否足够统一；
- 大型项目是否容易维护。

这也是 Go 和一些“功能丰富型”语言很重要的区别。

---

四、Go 是一门编译型语言

写 Go 程序时，我们通常会经历：

Go 源代码
    ↓
Go 编译器
    ↓
可执行文件
    ↓
运行

例如：

package main

import "fmt"

func main() {
    fmt.Println("Hello, Go!")
}

保存为：

main.go

然后执行：

go run main.go

你会看到：

Hello, Go!

也可以直接构建：

go build

最终得到一个可以运行的程序。

这带来了一个很重要的特点：

«Go 程序通常不需要像某些解释型语言那样，在目标机器上额外准备完整的语言解释环境。»

对于服务器程序、命令行工具和容器环境来说，这一点非常方便。

当然，“编译型语言”并不意味着 Go 程序一定比所有其他语言运行得快。

真正的性能取决于：

- 算法；
- 数据结构；
- 内存访问；
- 编译器；
- 运行时；
- IO；
- 并发模型；
- 程序本身的实现方式。

所以不要简单地把：

«“Go 是编译型语言”»

理解成：

«“Go 一定比其他语言快。”»

这不是严谨的结论。

---

五、Go 为什么强调静态类型？

Go 是一门静态类型语言。

例如：

var age int = 18

这里明确规定：

age → int

如果之后尝试把完全不兼容的数据直接赋给它，编译器通常就会发现问题。

静态类型的一个重要价值是：

«很多错误可以在程序运行之前被发现。»

这对于大型项目尤其重要。

假设一个项目只有几百行代码，那么很多问题可以通过测试和运行发现。

但是当项目变成：

10 万行
50 万行
100 万行

并且由几十甚至几百名开发者共同维护时，仅仅依赖运行时发现错误就会变得非常困难。

类型系统相当于给程序增加了一层约束。

它告诉编译器：

«“这个地方应该是什么东西。”»

于是编译器可以帮助我们提前发现一部分错误。

六、Go 的一个重要关键词：并发

如果要找一个最能代表 Go 的技术关键词，那么 Goroutine 几乎一定会出现。

Go 从语言和运行时层面提供了轻量级并发机制。

最简单的形式：

go doSomething()

在 "go" 关键字后面调用一个函数，就可以让这个函数以 Goroutine 的方式运行。

例如：

package main

import (
    "fmt"
    "time"
)

func hello() {
    fmt.Println("Hello from goroutine")
}

func main() {
    go hello()

    time.Sleep(time.Second)
}

这里的：

go hello()

就是 Go 并发模型的一个入口。

但这里有一个非常重要的学习原则：

«不要把 Goroutine 简单理解成“创建一个线程”。»

Goroutine 和操作系统线程不是一回事。

Go Runtime 会负责调度大量 Goroutine，并把它们映射到较少数量的系统线程上运行。

因此，一个 Go 程序可以创建大量 Goroutine。

当然，“可以创建很多”并不意味着“可以毫无节制地创建”。

后面的文章会专门讨论：

- Goroutine；
- Channel；
- select；
- sync；
- Context；
- 数据竞争；
- Goroutine 泄漏。

现在只需要记住：

«并发是 Go 语言设计中的核心能力，而不是后来附加上去的功能。»

---

七、Channel：让并发程序进行通信

Go 的另一个重要设计是 Channel。

例如：

ch := make(chan int)

一个 Goroutine 可以向 Channel 发送数据：

ch <- 10

另一个 Goroutine 可以接收：

value := <-ch

于是我们可以形成：

Goroutine A
     │
     │ 发送数据
     ▼
  Channel
     │
     │ 接收数据
     ▼
Goroutine B

这也是 Go 并发编程中非常重要的一种思想：

«不要通过共享内存来通信，而应该通过通信来共享内存。»

这句话并不意味着 Go 程序不能使用共享内存，也不意味着 Mutex 等同步工具不重要。

它更像是一种设计倾向：

«当多个并发任务需要协作时，可以考虑通过 Channel 建立明确的通信关系。»

后面学习并发时，我们会详细讨论什么时候应该使用 Channel，什么时候应该使用 Mutex。

八、Go 不只是“写后端”的语言

很多初学者第一次接触 Go 时，会把它简单理解成：

«“Go 是用来写后端的。”»

这并不准确。

Go 的应用范围非常广。

1. Web 服务

这是 Go 最常见的应用方向之一。

例如：

HTTP Server
API
微服务
网关
RPC 服务

Go 标准库本身就提供了比较完整的 HTTP 能力。

Go 在云原生基础设施领域非常常见。

例如很多基础设施软件都使用 Go 开发。

原因并不只是“Go 快”，还包括：

- 编译型语言；
- 静态类型；
- 并发能力；
- 网络库完善；
- 跨平台编译方便；
- 部署简单；
- 标准工具链统一。

因此开发者可以把它复制到目标机器后直接运行。

九、Go 和其他语言应该怎么比较？

初学者很容易陷入一个问题：

«Go、Python、Java、C++、Rust 到底哪个更好？»

这个问题本身就有问题。

编程语言不是手机型号。

并不存在一张简单的：

第一名
第二名
第三名

的排行榜。

更合理的问题应该是：

«针对某一种任务，哪种语言的综合成本更低？»

可以粗略地这样理解：

语言| 典型优势
C| 底层控制、系统编程
C++| 高性能、大型复杂软件、生态丰富
Java| 企业应用、成熟生态
Python| 开发效率、脚本、数据科学、AI
Rust| 性能、内存安全、底层系统
Go| 工程效率、并发、网络服务、基础设施

这并不是严格的语言能力排名。

同一个项目完全可能同时使用多种语言。

例如：

Python
   ↓
数据处理

Go
   ↓
API 服务

Rust / C++
   ↓
高性能组件

真正优秀的工程师不是“只会一种语言的人”。

而是知道：

«什么问题应该使用什么工具解决。»

十、学习 Go，不应该只学习语法

这是这套教程希望强调的一点。

如果我们只是按照：

变量
↓
if
↓
for
↓
函数
↓
struct
↓
interface

这样一直往下背语法，当然可以写出 Go 程序。

但你很可能会遇到一个问题：

«“我明明知道 Go 的语法，为什么还是写不好 Go 项目？”»

因为编程语言真正重要的部分，并不只是语法。

我们需要逐渐建立几个层次的认识：

语法
 ↓
数据结构
 ↓
抽象
 ↓
并发
 ↓
工程组织
 ↓
系统设计

例如：

学习 "slice" 时，不应该只知道：

numbers := []int{1, 2, 3}

还应该理解：

- slice 和 array 有什么区别？
- slice 的长度和容量是什么？
- slice 是否共享底层数组？
- append 发生了什么？
- 为什么某些情况下修改一个 slice 会影响另一个 slice？

学习 "interface" 时，也不应该只知道：

type Reader interface {
    Read()
}

而应该继续问：

- 为什么需要 interface？
- interface 如何实现解耦？
- 为什么 Go 使用隐式实现？
- interface 和具体类型之间是什么关系？
- interface 为 nil 时为什么有时会出现令人困惑的行为？

学习 Goroutine 也一样。

不要只记住：

go work()

而应该继续问：

- Goroutine 是什么？
- 谁负责调度？
- Goroutine 和线程有什么区别？
- 如何等待 Goroutine？
- 如何取消 Goroutine？
- 什么是数据竞争？
- 什么是 Goroutine 泄漏？

这才是学习 Go 的真正过程。

十二、第一段 Go 代码

现在，我们正式写一个 Go 程序。

创建：

main.go

写入：

package main

import "fmt"

func main() {
    fmt.Println("Hello, Go!")
}

然后：

go run main.go

输出：

Hello, Go!

虽然只有短短几行代码，但已经出现了几个之后会反复学习的概念。

"package main"

Go 程序由 Package 组成。

这里的：

package main

表示当前文件属于 "main" Package。

对于一个可以独立运行的 Go 程序，通常会有一个 "main" Package。

---

"import "fmt""

我们需要使用 Go 标准库中的 "fmt" Package。

所以：

import "fmt"

表示导入它。

之后就可以：

fmt.Println(...)

---

"func main()"

func main() {
}

这是程序的入口函数。

程序运行之后，会从 "main" 函数开始执行。

关于：

- "func"
- 参数
- 返回值
- Package
- import

我们现在不需要全部展开。

后面的文章会逐一解释。

十三、几个现在不需要急着理解的东西

刚开始学习 Go 时，经常会遇到这种情况：

看到一个陌生概念，就想马上把它彻底搞懂。

例如第一次看到：

func main() {
    fmt.Println("Hello, Go!")
}

可能马上产生一大堆问题：

«"func" 是什么？»

«"main" 是什么？»

«"fmt" 是什么？»

«"Println" 为什么首字母大写？»

«Package 到底是什么？»

«Go 程序到底怎么编译？»

这些问题当然都值得理解。

但没有必要在第一天把所有概念全部解决。

学习编程更像是不断建立一张知识网络。

第一次看到一个概念：

interface

可能只知道：

«“这是 Go 的一种类型机制。”»

后面学到：

struct
method
interface

之后，你会开始理解它们之间的关系。

等真正写 Web 项目时：

Handler
Service
Repository

大量使用 interface 时，你才会真正理解：

«原来 interface 是用来解决这个问题的。»

因此，这套教程会尽量避免一次性把所有知识塞给你。

我们会让概念在后续文章中不断出现。

十四、总结

这一篇没有讲很多 Go 语法。

我们主要建立了几个认识。

第一，Go 是一门面向工程实践设计的编程语言。

它并不是为了拥有最多的语法特性，而是强调：

- 简洁；
- 可读；
- 工具统一；
- 编译效率；
- 运行效率；
- 并发；
- 工程维护。

第二，Go 的重要价值之一是并发和网络编程能力。

Goroutine、Channel、Context 等机制，会成为后续学习的重要内容。

第三，Go 不只是 Web 开发语言。

它还广泛适用于：

- CLI 工具；
- 网络程序；
- 云原生软件；
- 基础设施；
- 服务端程序；
- 分布式系统。

最后，也是最重要的一点：

«学习 Go 的目标不是记住 Go 有哪些语法，而是逐渐学会用 Go 思考和解决问题。»

下一篇，我们正式从代码开始。

我们会安装 Go，创建第一个 Go 项目，并把：

go run
go build
go mod
package main
func main()

这些看似简单、但实际上非常重要的概念真正弄明白。
