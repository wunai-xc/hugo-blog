# 付费 Claude 计划的上下文窗口有多大？

Claude Sonnet 5 在所有付费计划中与 Claude 聊天时支持 1M 令牌上下文窗口。Claude Opus 4.8、Opus 4.7、Opus 4.6 和 Sonnet 4.6 在所有付费计划中与 Claude 聊天时支持 500K 令牌上下文窗口。除了这些模型外，Claude 的上下文窗口大小为 200K，这意味着在使用付费 Claude 计划时，它可以摄取 200K+ 令牌（约 500 页或更多文本）。

在使用 Claude Code 与 Pro、Max、Team 或 Enterprise 计划时，Claude Sonnet 5、Fable 5、Opus 4.8、Opus 4.7 和 Opus 4.6 支持 1M 令牌上下文窗口。Pro 用户需要启用使用额度才能访问 Opus 模型的 1M 令牌上下文窗口。Sonnet 4.6 也支持 Claude Code 上所有付费 Claude 计划的 1M 上下文窗口，但必须启用使用额度才能访问它（基于使用量的 Enterprise 计划除外）。

## 自动上下文管理

对于启用了代码执行的付费计划用户，Claude 会自动管理您的对话上下文。当您的对话接近上下文窗口限制时，Claude 会总结早期消息以为新内容腾出空间。这不计入您的使用限制，并且在大多数情况下允许对话无限期继续。

您的完整聊天历史记录被保留，以便 Claude 可以参考它，即使早期部分已被总结。在长对话中，您可能偶尔会注意到 Claude "整理思路"——这是自动上下文管理在起作用。

**注意：**必须启用代码执行才能使自动上下文管理工作。在极少数边界情况下（例如非常大的首条消息或系统错误），您仍可能遇到上下文窗口限制。

## 最大化您的上下文窗口

虽然上下文在大多数对话中自动管理，但您仍然可以优化如何使用可用的上下文空间：

- **有效利用项目：**项目使用检索增强生成 (RAG)，这允许 Claude 通过仅将相关内容加载到上下文窗口中来处理更大量的信息。

- **保持项目说明简洁：**当您使用项目说明来提供项目的一般背景、关键指南和 Claude 的角色时，Claude 表现最佳。

- **管理工具和连接器：**这些功能需要大量令牌，因此注意您有多少个活跃的功能有助于最大化您的可用上下文。
